# Rooms 0.2.26: recover transfers and reuse verified samples

This local build improves the file service used alongside FL Studio 24, 25 and 26. The reviewed
builds remain **24.2.2.4597, 25.2.5.5319 and 26.1.7.5654**. FL24 remains supported. This pass
does not add a new FL build profile or claim support for every update.

The main changes make direct downloads recover more reliably and let a recipient offer its
verified sample copy to other participants. Cloudflare still coordinates edits and permissions,
recorded notes keep their existing CRDT merge, and R2 remains the automatic file fallback.

## 35 improvements explained

1. **Trying another source now works reliably.** A failed source gets its own transfer state.
   A delayed close from that source cannot cancel the next source's download.
2. **Cancelled uploads release their slot.** Closing a file channel tells the local service
   to stop serving, so an abandoned upload cannot occupy one of the two outgoing slots.
3. **Cancellation also works during setup.** If a channel closes while its source file is
   still being admitted, the service cancels that pending request instead of starting it later.
4. **Stuck worker replies can be interrupted.** Cancellation stops waiting for a background
   chunk acknowledgment, releases its timer and removes its cancellation listener.
5. **Shutdown blocks queued commands.** Commands still waiting for the hidden worker to
   load cannot send after the service has closed.
6. **Old commands cannot reach a replacement worker.** Each send captures its intended
   window before waiting, then checks that the same window is still current.
7. **A failed worker load can retry.** The failed hidden window is destroyed and cleared,
   allowing a later request to create a fresh one.
8. **Replacement sessions ignore old events.** Internal worker session IDs rotate on native
   reconnection and signaling loss. Late readiness or file messages cannot change the new session.
9. **Old source reads stop on reset.** Outgoing reads check both the native connection and
   worker session identity before sending another chunk.
10. **Signaling reconnects back off.** Failed connections retry after 1, 2, 4 and later seconds,
    capped at 30 seconds. A valid participant list resets the delay.
11. **Participant lists receive stronger checks.** Duplicate IDs, malformed IDs and lists that
    omit the receiving participant are rejected before creating direct connections.
12. **Early connection candidates wait.** Network candidates arriving before the remote
    description are buffered until WebRTC can accept them, avoiding an unnecessary failure.
13. **That early-candidate queue has a ceiling.** More than 64 pending candidates closes the
    affected connection rather than accumulating unlimited setup work.
14. **Interrupted direct connections can restart ICE.** The designated offerer can attempt
    reconnection after failure or disconnection, with a three-attempt limit until connected.
15. **Removed peers stop retrying.** Departure/reset clears their recovery timers, and old
    callbacks cannot announce readiness or send candidates for a removed connection.
16. **Browser-buffer draining resumes uploads.** A sender now wakes when its WebRTC buffer
    drains, even if no additional acknowledgment arrives to wake it.
17. **Timed-out writes clean up the transfer.** A blocked chunk that reaches its timeout
    cancels the channel and rejects the pending reply, instead of leaving a half-alive sender.
18. **Invalid chunks stop earlier.** Empty chunks, chunks over 32 KiB and bytes beyond the
    advertised file size are rejected before forwarding them to the local download service.
19. **An early end cannot complete a short file.** The worker requires the exact advertised
    byte count before forwarding completion. Native SHA-256 verification remains in place.
20. **Tiny-message floods are bounded too.** Queues stop at 64 pending messages as well as
    the existing byte ceiling, preventing many small messages from creating excessive promises.
21. **Acknowledgments must move forward.** They must follow a serving request and acknowledge
    newly sent bytes. Repeated or invalid progress cannot keep waking a blocked sender.
22. **Duplicate download starts are rejected.** The local service cancels the transfer rather
    than attempting to write response headers a second time.
23. **Duplicate serving IDs cannot reserve twice.** A repeated outgoing identifier is rejected
    before opening another file handle or consuming another slot.
24. **Finishing and declining files clear old timers.** Switching to the short closing timeout
    clears the previous transfer timeout, including the missing-source path.
25. **A busy local peer cannot trigger an R2 quota pause.** Local 429/507 responses fall back
    to R2 without treating them as a cloud storage allowance or stopping room sharing.
26. **Recipients can serve verified samples onward.** Existing matching files, verified cache
    hits and completed downloads register with the local file service. Temporary or unverified
    downloads are not registered.
27. **Unchanged files avoid repeated registration.** A successful registration is remembered
    for that native connection, so repeated shared edits avoid another local registration call.
28. **Changed files and new sessions can register again.** Size, modification time or hash
    changes clear that marker; reconnecting uses a new generation. Failed registrations are
    not marked successful.
29. **Registration requires an active native generation.** The native sender and local service
    refuse generation-zero registration, keeping file offers tied to a negotiated connection.
30. **Local JSON requests must be objects.** Null, arrays and scalar bodies are rejected as
    malformed requests instead of reaching connection or file-registration handling.
31. **The local Host must match the actual port.** Authentication also checks the exact
    bound loopback address and port, in addition to the existing token and origin restrictions.
32. **Download numbers use an explicit format.** Byte counts and generations require decimal
    digits; missing values and scientific notation cannot pass through numeric coercion.
33. **A partial request cannot revive a dropped session.** Connection handling rechecks that
    the launch still exists after waiting for the request body.
34. **Logging failures cannot invalidate a completed download.** Thrown exceptions and rejected
    diagnostic writes are contained after transfer completion.
35. **Temporary credential buffers are cleared more consistently.** Welcome validation and
    native HTTP cleanup clear their temporary token/header buffers on more exit paths.

## Verification

The [QA report](../../client/desktop/QA-0.2.26.md) records the final checks and artifact hash.
The new worker and adapter tests exercise actual shipped source with controlled channels,
timers and IPC. The Electron integration test uses three isolated launch sessions, five direct
downloads of a 2,097,171-byte sample, simultaneous transfers, a worker crash, alternate-source
recovery, onward serving and one forced R2 fallback.

These are local fixtures and loopbacks. They do not prove physical MIDI, remote NAT traversal,
every plugin version or every FL patch. The earlier intermittent FL24 recovery-save stall
remains unresolved. No user FL process, project or licensing state was operated in this pass.
No GitHub push, PR or Cloudflare deployment was made.
