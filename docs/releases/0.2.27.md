# Rooms 0.2.27: channel operations and browser-sample reliability

This build adds 57 fixes and safeguards around shared channels, samples dragged from
FL's browser, room launch and background file work. It includes the earlier local 0.2.26
transfer-recovery work.

The reviewed FL builds remain **24.2.2.4597, 25.2.5.5319 and 26.1.7.5654**. FL24 remains
supported. The changes strengthen common paths used by those profiles; they do not establish
support for every FL patch, every plugin state or every newer project opened in an older FL.

## Channels and channel order

1. **Check the destination before adding a channel.** A received add must identify a channel
   and the next available index. A mismatched target pauses sharing before calling FL.
2. **Confirm that FL actually added one channel.** A non-null return alone no longer counts
   as success. The list must grow by exactly one before flim updates its own records.
3. **Check which channel FL returned.** The returned object must be the newly appended
   channel, preventing a preset from being applied using an unrelated returned object.
4. **Protect existing channel identities during an add.** flim verifies the previous
   channels stayed in place before it commits the new channel's bookkeeping.
5. **Detect stale delete targets.** A deletion for a channel that no longer exists now
   pauses unsafe sharing instead of silently allowing the two channel lists to diverge.
6. **Keep bookkeeping after a failed deletion.** A native exception, no-op or wrong channel
   count no longer shifts plugin and note associations as though deletion succeeded.
7. **Verify the surviving channels after deletion.** Removing the wrong channel is detected
   before flim shifts indices, which protects subsequent edits from reaching the wrong sound.
8. **Reject invalid reorder sizes.** Missing orders and negative or excessive counts stop
   before reading the requested permutation or changing channel selection.
9. **Skip unchanged channel orders.** An identity permutation returns immediately, avoiding
   needless selection changes and note, clip and metadata baselining.
10. **Restore channel selection after a move faults.** Selection restoration runs outside the
    faulting move block and guards each channel separately.
11. **Stop replaying edits against an incorrect order.** When FL cannot reproduce the requested
    order, flim pauses sharing and reports the mismatch while leaving FL open.

## Sample identities and attaching files to edits

12. **Clear failed file hashes.** Failed opens, allocation, reads or hashing leave an empty
    result, preventing callers from reusing a previous or incomplete fingerprint.
13. **Check session identity before cached sample hashes.** Canceled work cannot reuse a
    cached fingerprint to prepare an edit for a different connection.
14. **Reject empty sample sources earlier.** Zero-byte audio does not enter the attachment
    and transfer path as a usable sample.
15. **Recheck after hashing.** A changed file or canceled connection clears the result before
    the hash enters the cache.
16. **Cancel cached file searches cleanly.** Hash lookups check the current session and clear
    their output path on entry; a failed search cannot leave a previous filename behind.
17. **Bound accumulated sample-path mappings.** New mappings stop at 8,192 entries rather
    than growing indefinitely during long sessions. Existing mappings can still be updated.
18. **Validate the operation before sample I/O.** The attachment code parses the actual JSON
    operation and requires an object before preparing or sending its files.
19. **Refuse duplicate sample metadata.** An operation already containing a samples field is
    rejected instead of producing duplicate JSON keys with ambiguous meaning.
20. **Stop on a damaged preset image.** A failed preset walk aborts sample preparation before
    the transfer stage.
21. **Observe cancellation while collecting samples.** A stale connection or sharing fault
    stops attachment work before another file is prepared.
22. **Check the hashed size against the transport limit.** A source that grew after its
    earlier inspection cannot slip past the per-file limit.
23. **Attach metadata to formatted JSON correctly.** The code locates the parsed operation
    rather than relying on one exact spacing pattern, preserving the operation's fields.
24. **Handle empty operation objects correctly.** Adding sample metadata to an empty object
    no longer creates an invalid leading or trailing comma.

## Native upload and download handling

25. **Hold upload sources stable while streaming.** The native file handle allows readers,
    while excluding writes and deletion for the duration of its upload read.
26. **Check the opened upload's exact size.** A changed source or size outside WinHTTP's
    request-length range is refused before sending the authenticated request.
27. **Validate request-path conversion.** Invalid UTF-8 and an overlong combined path fail
    cleanly before passing an invalid path to WinHTTP.
28. **Require a readable HTTP status.** Failure to obtain response status now fails the
    request rather than treating an unconfirmed result as usable.
29. **Reset HTTP result buffers.** Response text and download hashes start empty; an
    unsuccessful download clears its hash so old response data cannot imply success.
30. **Keep per-file progress consistent on retry.** A retry restores that file's saved
    starting progress rather than unconditionally resetting it to zero.
31. **Retry upload content conflicts automatically.** HTTP 409 on an upload marks the
    pending operation for retry, allowing its next preparation to rehash the source.
32. **Give multi-source direct downloads enough receive time.** The native receive timeout
    is 12 seconds, accommodating the bounded attempts made by the direct-file service.

## Direct-file service and connection recovery

33. **Reject malformed UTF-8 request bodies.** The local file service uses fatal decoding,
    preventing replacement characters from changing the meaning of a request.
34. **Reject alternate request authorities.** Absolute-form and double-slash request targets
    fail before routing through the loopback service.
35. **Keep connection generations in native range.** Values above the positive signed
    32-bit range are refused instead of disagreeing with the engine's generation counter.
36. **Validate tracked FL process IDs.** Lifetime tracking accepts only positive integer
    Windows process IDs within range.
37. **Detect replaced source files more accurately.** Offers capture file identity and
    change time as well as size and modification time; serving rechecks that metadata.
38. **Remove unusable source offers.** If source admission fails, the invalid offer is
    discarded so later requests do not repeatedly probe the same dead registration.
39. **Wait for outgoing file cleanup on shutdown.** The service tracks asynchronous serving
    jobs and waits for their finalizers, including file-handle closure.
40. **Contain signaling send failures and backlog.** A throwing send or more than 64 KiB
    of buffered signaling closes that connection instead of escaping or queuing more traffic.
41. **Time out an incomplete signaling admission.** A connection that never supplies a valid
    participant list closes after ten seconds and enters the existing recovery path.
42. **Remove departed peers from readiness immediately.** A valid updated participant list
    removes old ready entries before the worker handles the new membership.
43. **Allow time to reach a later file source.** The first-byte deadline accounts for the
    available sources, up to ten seconds, instead of canceling the whole request after
    1.5 seconds while a later source is still starting.
44. **Try another peer when data-channel creation throws.** Failure to create the first
    source's channel advances to the next connected candidate before falling back to R2.
45. **Continue ICE recovery without another state event.** A connection remaining failed or
    disconnected schedules another bounded attempt, up to the existing three-attempt budget.

## Room launch, installation discovery and Files status

46. **Keep a confirmed FL launch confirmed.** An optional direct-file lifetime-tracking error
    cannot turn a successful launch into an uncertain result that invites a duplicate launch.
47. **Preserve definite launch errors during cleanup.** A failed optional cancellation cannot
    hide the real launcher error. The unsuccessful launch's room-folder binding is cleared.
48. **Recheck room expiry after direct-file preparation.** If the reservation expired while
    waiting, flim cancels the optional preparation and refuses to launch with stale credentials.
49. **Refresh native-payload readiness on initialization.** A payload removed since a previous
    check no longer leaves a stale ready state.
50. **Keep the newest installation scan.** A slower earlier scan cannot overwrite the
    selected installation and results of a more recent scan.
51. **Contain diagnostics-availability failures.** A failing optional status probe cannot
    prevent the main application state from being returned.
52. **Explain a missing installation-folder chooser.** The action returns an instruction
    to reopen the complete app instead of throwing an unhelpful missing-function error.
53. **Clean participant-name Unicode before display.** Malformed Unicode is repaired and
    additional invisible and direction-formatting characters are removed.
54. **Preserve the original local-read failure.** If a failed read also encounters a file-close
    error, the read error remains the reported cause rather than being hidden by cleanup.
55. **Reject malformed filenames in Files status.** Invalid UTF-16 strings cannot pass the
    status parser and reach the renderer as broken filename text.
56. **Bound status-directory processing.** More than 4,096 entries stops processing before
    opening status files and preserves the previously confirmed activity as stale.
57. **Cancel unsuccessful relay response reads.** The JSON response reader attempts cancellation
    before releasing its lock on an error, reducing abandoned response work.

## Verification and remaining limits

The [0.2.27 QA record](../../client/desktop/QA-0.2.27.md) records checks, artifact details and
test scope. The channel tests use owned synthetic native objects. The HTTP tests execute the
real native transfer code against ephemeral local servers. The direct-file integration uses
real Electron WebRTC and local Cloudflare emulation.

No user FL process, project, installation or licensing state was operated during this pass.
Physical MIDI, two-computer internet sessions, remote NAT behavior and all VST state versions
still need separate live coverage. The earlier intermittent FL24 recovery-save stall remains
unresolved. A native fault or channel-list mismatch can pause sharing while FL remains open.

Recorded-note CRDT behavior, missing-plugin isolation, the older receiver's shared-note/basic-
control fallback, room ownership and R2 safety guards remain in place. Onward file serving
does not transfer ownership; the host's native departure still ends the room. No TURN service
was added. Validation ran locally before GitHub review. This contribution does not deploy
Cloudflare or publish a new executable release; the recorded artifact hash describes the local build.
